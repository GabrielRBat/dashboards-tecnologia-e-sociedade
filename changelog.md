# changelog.md — Histórico de Mudanças

Formato: **data** — tipo — descrição.

## 2026-08-24

- **2026-08-24** — docs — Criação inicial do projeto: `AGENT.md` (instruções do agente), `context.md` (contexto do projeto) e `changelog.md` (este arquivo).
- **2026-08-24** — docs — Criação do `CLAUDE.md` apontando para `AGENT.md`, `context.md` e `changelog.md`, para que o Claude Code carregue as instruções automaticamente no início de cada sessão.
- **2026-08-24** — docs — Definição da arquitetura com o usuário: app web com login, Next.js + NestJS (TypeScript), PostgreSQL + Prisma, importação de Excel/CSV, hospedagem em nuvem. Criado `ESPECIFICACOES.md` e atualizado `context.md`.
- **2026-08-24** — docs — Análise da "Planilha de Registro e cálculo". Domínio corrigido: é P&D de formulações de argamassa, não controle de qualidade de obra. Mapeadas as 202 colunas e as fórmulas; constatado que só a linha 11 tem ensaios preenchidos.
- **2026-08-24** — refactor — Troca de **Prisma por Drizzle ORM**. O Prisma baixa binários de fora do npm, o que impedia criar o banco e testar; Drizzle é TypeScript puro via npm e remove essa dependência também em rede restrita e em hospedagem.
- **2026-08-24** — feature — Estrutura do monorepo (npm workspaces): `apps/api`, `apps/web`, `packages/shared`, `docker-compose.yml` com Postgres 16 e `.env.example`.
- **2026-08-24** — feature — Modelo de dados no Drizzle (6 tabelas), migração inicial e seed determinístico com 64 formulações e 36 materiais. Materiais viraram cadastro no lugar das 36 colunas fixas da planilha.
- **2026-08-24** — feature — Módulo de cálculos do laboratório com 25 testes unitários que reproduzem os números reais da planilha (densidade 1.574,61 kg/m³; retenção de água 86,97%; volume do CP 265,523175 cm³).
- **2026-08-24** — fix — Correção de três fórmulas erradas da planilha: módulo de elasticidade dinâmico (velocidade não elevada ao quadrado e fator de Poisson que se cancela), relação água/ligante (invertida) e densidade média no estado endurecido (método inconsistente entre 14 e 28 dias). Documentado em `docs/CALCULOS.md`, com a fórmula antiga preservada para conferência.
- **2026-08-24** — feature — API NestJS: formulações com filtros e paginação, indicadores agregados, cadastro de materiais, verificação de saúde e importação da planilha `.xlsx` (idempotente por numeração).
- **2026-08-24** — feature — Frontend Next.js: visão geral com indicadores e cinco gráficos, lista de formulações com filtros na URL, página de detalhe e tela de importação. Modo claro e escuro.
- **2026-08-24** — fix — Ajustes da revisão visual: rótulos sobrepostos no gráfico por tipo de projeto, vão na grade de gráficos, favicon ausente (404), legenda redundante em gráfico de série única e animação de entrada que atrasava a leitura dos valores.
- **2026-08-24** — fix — Seed gerava retenção de água fisicamente impossível (21% a 144%) por sortear M0, M1 e M2 de forma independente. Passou a sortear a retenção alvo (78–98%) e derivar M2 pela fórmula do ensaio.
- **2026-08-24** — docs — README reescrito, criado `docs/CALCULOS.md` e atualizados `context.md` e `ESPECIFICACOES.md`.
- **2026-08-24** — feature — Aba **Configurações** com escolha de tema (Automático, Claro, Escuro), com prévia visual de cada opção. A preferência fica no `localStorage` e um script no `<head>` a aplica antes da primeira pintura, evitando o flash claro. Verificado com 14 cenários automatizados, incluindo persistência entre páginas e recarga, a opção Claro vencendo um sistema no escuro, e o caso de navegador com armazenamento bloqueado.
- **2026-08-24** — fix — `npm run db:seed` falhava com "DATABASE_URL não definida" porque o `.env` precisava ser copiado para dois lugares (raiz e `apps/api`). Agora a API procura o `.env` subindo os diretórios: **um único arquivo na raiz basta**. As mensagens de erro passaram a dizer o que fazer em cada caso — `.env` ausente (com o comando do PowerShell e do bash), banco fora do ar e migrações não aplicadas. Corrigida também a menção a Prisma que ainda estava no `.env.example`, e o README ganhou instruções separadas para Windows.
- **2026-08-24** — fix — `npm run dev` usava `&` do bash para rodar API e frontend em paralelo. No Windows o `cmd.exe` interpreta `&` como execução **sequencial**, então o frontend nunca subia. Trocado por `concurrently`, que funciona nos dois sistemas. Verificado: os dois serviços respondendo simultaneamente.
- **2026-08-24** — feature — Script `subir.ps1` que sobe o projeto do zero no Windows, conferindo Node, `.env`, PostgreSQL (via Docker ou instância existente), dependências, migrações e seed, parando com instrução clara em cada pré-requisito que faltar.
- **2026-08-24** — fix — `subir.ps1` não rodava: o arquivo estava em UTF-8 **sem BOM** e o Windows PowerShell 5.1 o lê como CP1252, onde o travessão `—` (`E2 80 94`) vira `â€"` — e esse último caractere é `"` (U+201D), que o PowerShell aceita como fecha-aspas. A string terminava no meio e o parse do arquivo inteiro quebrava. Salvo com BOM.
- **2026-08-24** — fix — A porta do PostgreSQL no host virou configurável (`DB_PORT` no `.env`, lida pelo `docker-compose.yml`). Antes era fixa em 5432, e numa máquina que já tem PostgreSQL próprio o banco do projeto não subia.
- **2026-08-24** — fix — `subir.ps1` tratava qualquer coisa escutando na porta como sendo o banco do projeto e seguia adiante, quebrando só depois, na migração, com um erro de autenticação sem explicação. Agora ele distingue o container `argamassas-db` de um PostgreSQL alheio, avisa quando não é o do projeto, e as mensagens de falha (Docker e migração) apontam o conflito de porta e como resolvê-lo.
- **2026-08-24** — fix — `explicarErro` (API) não cobria credencial recusada, o sintoma mais provável de conflito de porta. Passou a explicar a causa e mostrar as duas linhas do `.env` a ajustar.
- **2026-08-24** — docs — README ganhou a seção "Se a porta 5432 já estiver ocupada"; `context.md` registra o PostgreSQL 17 nativo desta máquina (projeto na 5433) e a exigência de BOM nos arquivos `.ps1`.
